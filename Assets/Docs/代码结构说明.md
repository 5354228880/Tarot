# 代码结构说明

> 面向协作者的简版说明。当前 MVP 的玩法代码集中在 `Assets/Scripts/Core` 与 `Assets/Scripts/Game`；旧版 UI 和编辑器工具单独标注。
> 规则细节见 `策划案_v0.1.md`，范围见 `MVP构建.md`，效果映射见 `卡牌效果表.md`。

## 1. 模块划分

```text
Assets/Scripts/Core        Tarot.Core.asmdef（纯 C#，不引用 UnityEngine）
  规则、数据模型、牌库、序列、结算、效果、随机

Assets/Scripts/Game        当前在 Assembly-CSharp（MVP 暂未拆 asmdef）
  场景入口、GameSession、战斗 UI、拖拽、卡牌视图、运行时 UI 工厂

Assets/Scripts/UI          旧版主菜单/设置/选关/关卡脚本（部分仍被主菜单使用）
Assets/Editor              编辑器工具、场景生成器
```

依赖方向：

```text
Editor → Game / Legacy UI → Core
Core 不依赖以上任何一层，也不依赖 UnityEngine。
```

原则：

- **Core 只做规则**，可以在没有场景的情况下测试。
- **Game 只做显示与输入**，不写战斗规则。
- **卡牌是数据**，不是“一牌一类”；效果由 `EffectDef` 原语组合。

## 2. Core：数据模型

文件：`Assets/Scripts/Core/CardModel.cs`

| 类型 | 作用 | 主要成员 |
|---|---|---|
| `CardDefinition` | 静态牌面数据 | `Id`、`Name`、`Arcana`、`Suit`、`Rank`、`Upright`/`Reversed` 效果、显示文本、`EnemyHp`、`EnemyDamage`、`IsImplemented` |
| `EffectDef` | 一条效果数据 | `Primitive`、`Target`、`Flat/N/M`、百分比、`FlipType`、`Direction`、`Placement`、`Count`、`Pool`；`Amount()`、`Percent()` |
| `CardInstance` | 战斗中的一张牌 | `Def`、`Owner`、`BaseReversed`、`TurnFlip`、`LevelFlip`、`M`、`Zone`、变换前牌面；`IsReversed`、`TransformTo()`、`Restore()` |
| `Combatant` | 生命状态 | `MaxHp`、`Hp`、`Shield`、`Alive` |
| `Enemy` | 一个敌人 | `Card`、`Stats`、`Placement`、`SlotIndex`、`Alive` |
| `Slot` | 序列中的一个格子 | `Index`、`IsPlayerSlot`、`PlayerCard`、`Enemy`、`IsEmpty`、`Card` |
| `CardState` | 跨关卡持久化状态 | `BaseReversed`、`M` |
| `PendingBuff` | 下一张牌的待结算加成 | `Kind`、`Percent` |
| `ResolutionPlan` | 一次结算的顺序 | `Forward`、`Backward`、`Skip`、`UseBoth`、`UseBackward`、`DirectionLabel` |
| `DeckState` | 取牌堆/手牌/弃牌堆 | `ResetForLevel()`、`Draw()`、`Reshuffle()`、`RemoveFromHand()` |
| `RunState` | 一整局 | `Hp`、`DeckIds`、`CardStates`、`LevelIndex`、`Seed`、`IsComplete` |
| `CombatState` | 单场战斗 | `Player`、`Enemies`、`Deck`、`Sequence`、`Turn`、`Phase`、`Log`、`LockedTarget()`、`AllEnemiesDead` |
| `SequenceState` | 固定 9 个序列格 | `Slots` |
| `Rng` | 带种子的随机 | `Next()`、`Chance()`、`Shuffle()` |

枚举：`Arcana`、`Suit`、`Owner`、`Zone`、`FlipType`、`Primitive`、`TargetSelector`、`BuffKind`、`DirectionMode`、`PlacementRule`、`CombatPhase`、`TransformPool`。

约定：

- `n`：小阿卡纳点数 1~10。
- `m`：整局累计，只统计**关卡翻转/永久翻转**；回合翻转不计入。
- 有效正逆位：`BaseReversed XOR TurnFlip XOR LevelFlip`。
- `RunState.CardStates` 负责让 `m` 和永久翻转跨关卡保留。

## 3. Core：服务类

### `CardCatalog`

文件：`Assets/Scripts/Core/CardCatalog.cs`

静态卡牌数据库，构建当前 MVP 的 35 张牌。

| 方法/属性 | 作用 |
|---|---|
| `Get(id)` | 按 Id 取 `CardDefinition` |
| `StartingDeck()` | 初始 17 张牌（16 小 + 1 大） |
| `Encounter(level)` | 第 0~2 关小怪、第 3 关 Boss 的敌人 Id |
| `ImplementedMajors` / `ImplementedMinors` | 魔术师变换池、可选牌池 |
| `All` | 全部已实现牌 |

新增卡牌通常改这里；不需要新建卡牌类。

### `CombatEngine`

文件：`Assets/Scripts/Core/CombatEngine.cs`

无状态规则引擎，所有方法都是静态的，直接操作 `CombatState`。

| 方法 | 作用 |
|---|---|
| `CreateCombat(run, level)` | 建牌堆/玩家/敌人，抽首回合 6 张，处理魔术师，插入敌人 |
| `StartTurn` / `EndTurn` | 新回合抽 4 张；清理序列、护盾、回合翻转；恢复变换；重新插入敌人 |
| `PlaceCard` / `ReturnCard` | 手牌放入空位 / 序列牌撤回手牌 |
| `TryBeginAntiDefy` | 校验并弃 1 张手牌，进入抗逆选择状态 |
| `ApplyAntiDefyAll` / `ApplyAntiDefyHand` | 敌方全体永久翻转 / 单张手牌关卡翻转 |
| `BuildPlan` | 生成结算顺序；处理愚者跳过首尾、命运之轮方向 |
| `ResolveSlot` | 结算一个序列格；处理重复、待结算 Buff、死亡与重定向 |
| `SaveToRun` | 保存 HP、`BaseReversed`、`m` 到 `RunState` |
| `CardText` / `HasReversedWheel` / `AliveEnemies` / `GetSlot` | UI 辅助查询 |

内部关键逻辑：

- `ResolveEffect`：按 `Primitive` 执行伤害/治疗/护盾/加成/翻转/自伤/抽牌。
- `ApplyDamage`：先扣护盾，再扣血；检查玩家死亡与敌人死亡。
- `ApplyFlip`：切换正逆位；仅 Level/Permanent 增加 `m`。
- `ApplyTurnStartTransforms`：魔术师回合开始变换。
- `InsertEnemies`：随机插入敌人，并处理愚者放置规则。

## 4. Game：流程与表现

目录：`Assets/Scripts/Game`

### 流程入口

| 类 | 作用 | 主要方法 |
|---|---|---|
| `GameSession` | 跨场景单例，持有 `RunState` | `EnsureRun()`、`CurrentLevel`、`AdvanceLevel()`、`SaveCombat()`、`DiscardRun()` |
| `LayerBootstrap` | 层界面：4 个节点、HP/进度、返回主菜单 | `Start()` 构建 UI；当前节点加载 `Combat` |
| `CombatBootstrap` | 战斗场景入口 | `Start()` 创建相机/EventSystem，并挂 `CombatController` |

### 战斗 UI

| 类 | 作用 | 主要成员 |
|---|---|---|
| `CombatController` | 战斗总控制器 | 构建 UI、`RenderAll()`、`HandleDrop()`、`HandleDoubleClick()`、`ResolveRoutine()`、`ShowResult()`、暂停/设置 |
| `CardView` | 单张牌的显示与输入 | `Setup()`、`OnBeginDrag/OnDrag/OnEndDrag`、`OnPointerClick` |
| `SlotView` | 序列格标记 | `Index`、`IsPlayerSlot`、`SetColor()` |
| `DropZoneView` | 手牌区/弃牌区落点 | `Type`（Hand/Discard） |
| `UiFactory` | 运行时 UI 工厂 | `CreateCanvas`、`EnsureCamera`、`EnsureEventSystem`、`CreatePanel`、`CreateText`、`CreateButton`、`ScaleFonts`、布局辅助 |

`CombatController` 的主流程：

1. `Start()`：建 UI，取 `GameSession.Run`，创建 `CombatState`。
2. `RenderAll()`：根据状态重建序列牌、手牌、状态栏、日志、按钮和“当前结算”高亮。
3. 拖拽：`HandleDrop()` 判断落点，调用 `PlaceCard` / `ReturnCard` / `TryBeginAntiDefy`。
4. 抗逆：`HandleDoubleClick()` 处理敌方全体或手牌单张翻转。
5. 开始结算：`ResolveRoutine()` 逐格调用 `ResolveSlot`，每格高亮 0.12 秒、结算后停顿 0.22 秒。
6. 胜负：`ShowResult()`；小关保存并回 Layer，大关/死亡回 Menu。

### 字体与布局

- `UiFactory.FontScale = 1.22f`：所有运行时 UI 的字体统一放大。
- `UiFactory.ScaleFonts(root, factor)`：给旧版主菜单/设置面板做整体放大。
- 卡牌排版：序列牌 150×210，手牌宽度根据手牌数量在 76~90 之间自适应。
- 当前结算牌：金色 tint + 金色描边，并在序列上方显示 `RESOLVING: 牌名`。

## 7. 一次战斗的数据流

```text
Menu
 └─ MainMenu.OnPlay()
      └─ GameSession.DiscardRun() → Scene "Layer"
           └─ LayerBootstrap
                └─ GameSession.EnsureRun() → RunState
                     └─ 点击当前节点 → Scene "Combat"
                          └─ CombatBootstrap → CombatController
                               ├─ CombatEngine.CreateCombat(RunState, level)
                               │    └─ CombatState
                               ├─ RenderAll() → CardView / SlotView
                               ├─ 拖拽/双击 → CombatEngine
                               └─ 开始结算 → BuildPlan → ResolveSlot 循环
                                    └─ 胜负 → SaveToRun / AdvanceLevel / DiscardRun
```

## 8. 常见改动位置

| 想改什么 | 去哪里 |
|---|---|
| 新增一张牌 | `CardCatalog` 加定义；必要时在 `EffectDef` 组合原语；加入初始牌组/遭遇 |
| 新增效果原语 | `Primitive` + `CombatEngine.ResolveEffect` + 单测 + `卡牌效果表.md` |
| 改敌人配置 | `CardCatalog.Encounter` |
| 改关卡数量/层结构 | `CardCatalog.Encounter` + `LayerBootstrap` 的节点数 |
| 改战斗 UI | `CombatController` 的 `BuildUi`/`RenderAll`，样式走 `UiFactory` |
| 改卡牌外观 | `CardView.Setup` |
| 改字体/布局 | `UiFactory.FontScale`、`ScaleFonts`、各 `SetAnchored` |
| 加存档/继续 | `RunState`、`GameSession`；Core 数据已经可序列化 |
| 加音效/动画 | `CombatController` 的结算协程、`CardView`；Core 不改 |

## 9. 当前注意点

- `Core` 已经是独立 asmdef；`Game` 暂在 `Assembly-CSharp`，后续可拆 `Tarot.Game.asmdef`。
- 卡牌数据目前在代码里的 `CardCatalog`，不是 ScriptableObject。
- 没有自动化测试；规则验证目前靠编辑器 Play + MCP 调试。
- `LevelSelect` / `Level1` 是旧场景，不在 MVP 流程中。
- `GameManager.LevelScenesName` 仍是旧的占位数据，不要作为现有关卡来源。
